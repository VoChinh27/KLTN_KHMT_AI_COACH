QUY ƯỚC ĐỌC TÀI LIỆU
--------------------------------------------------------------------------------

PHẠM VI HỆ THỐNG:
  - Input : video 2D monocular (1 camera), không calibration
  - Pose  : 2D keypoints từ pose estimation model
  - Ràng buộc: KHÔNG có đơn vị vật lý tuyệt đối (cm, m)
  - Hệ quả : Mọi metric khoảng cách PHẢI là relative / normalized

PHÂN LOẠI NGUỒN (2 tầng tách biệt):
  [A] NGUỒN TIÊU CHUẨN KỸ THUẬT
      T1 = Số trực tiếp từ tài liệu điền kinh
      T2 = Quy đổi hợp lý từ T1
      T3 = Giả định kỹ thuật do hệ thống đặt

  [B] PHƯƠNG PHÁP ĐO BẰNG 2D POSE
      D1 = Đo trực tiếp, đáng tin (chủ yếu là góc khớp)
      D2 = Đo tương đối, cần normalize (khoảng cách, ratio)
      D3 = Ước lượng, độ tin cậy thấp (cần flag)

  QUAN TRỌNG: T1 KHÔNG đồng nghĩa D1.
  Ví dụ: "hông cao hơn vai 10-20cm" là T1 (chuẩn kỹ thuật),
  nhưng đo bằng 2D chỉ đạt D2 (tương đối). Không đánh đồng hai thứ.

QUY ƯỚC GÓC:
  - Góc khớp: đo BÊN TRONG khớp
      0°   = duỗi hoàn toàn
      180° = gập hoàn toàn (với gối, khuỷu)
  - Góc thân: đo SO VỚI PHƯƠNG THẲNG ĐỨNG (trong ảnh)
      0°  = thẳng đứng
      90° = nằm ngang

QUY ƯỚC TRỤC CƠ THỂ (2D):
  - Trục dọc      : từ hông -> vai (trong mặt phẳng ảnh)
  - Trục ngang    : từ vai trái -> vai phải (trong mặt phẳng ảnh)
  - Trục trước-sau: KHÔNG đo được chính xác trong 2D monocular

LƯU Ý PERSPECTIVE:
  - Camera phải quay VUÔNG GÓC với mặt phẳng chuyển động
  - Nếu camera lệch góc > 15°, các metric khoảng cách ngang/dọc
    bị sai lệch -> cần flag "perspective_warning"
  - Các metric góc khớp ít bị ảnh hưởng hơn -> ưu tiên scoring
QUY ƯỚC SỐ & LÀM TRÒN:
  - Góc (degree)       : làm tròn 1 chữ số thập phân   (vd: 92.5°)
  - Ratio              : làm tròn 3 chữ số thập phân   (vd: 0.985)
  - Slope              : làm tròn 4 chữ số thập phân   (vd: 0.0312)
  - Frame ID           : số nguyên                     (vd: 47)
  - Confidence         : số nguyên 0-100               (vd: 87)
  - Pixel (px)         : số nguyên                     (vd: 320)
  - Boolean            : True / False (Python style)
  
  LÝ DO:
    - Đảm bảo output đồng nhất giữa các module
    - Tránh sai số floating-point khi so sánh ngưỡng
    - Dễ đọc trong báo cáo

  step_length_trend
    công thức: slope của step_length_norm qua các bước
    step_length_norm = step_length_px / shoulder_width_px
    reference: > +3% per step (tolerance ε = 0.03)
      # KHÔNG dùng "> 0" tuyệt đối
    source   : T1 (khái niệm) / T3 (ε) / D2 (đo)
    scoring  : SECONDARY
    warning  : PHẢI làm mịn dữ liệu trước khi tính slope
               (xem Mục 7.7 - FPS Handling)

  contact_position_convergence
    công thức: slope của lateral_offset_norm qua các bước
    lateral_offset_norm = |x_contact - x_body_center| / shoulder_width
    reference: < -3% per step (tolerance ε = 0.03)
      # KHÔNG dùng "< 0" tuyệt đối
    source   : T1 / T3 / D2
    scoring  : SECONDARY
    warning  : PHẢI làm mịn dữ liệu trước khi tính slope

  cadence_trend
    công thức: slope của cadence trong 5-8 bước đầu
    reference: > +5% total
      # KHÔNG dùng "> 0" tuyệt đối
    source   : T1 / T3 / D1
    scoring  : SECONDARY
    warning  : cần FPS >= 60 để đo chính xác
               nếu FPS < 60 -> PHẢI làm mịn (xem Mục 7.7)

7.1. QUY ƯỚC TÍNH GÓC
--------------------------------------------------------------------------------
# Góc khớp (knee, elbow): đo BÊN TRONG khớp
#   0°   = duỗi hoàn toàn
#   180° = gập hoàn toàn
def joint_angle(a, b, c):
    v1 = a - b
    v2 = c - b
    norm_product = norm(v1) * norm(v2)
    if norm_product == 0:
        return 0.0
    # Dùng np.clip để tránh lỗi NaN do sai số số thực vượt quá [-1.0, 1.0]
    cosine = np.clip(dot(v1, v2) / norm_product, -1.0, 1.0)
    return degrees(arccos(cosine))

# Góc thân so với phương thẳng đứng (trong mặt phẳng ảnh)
def trunk_angle_vertical(shoulder_mid, hip_mid):
    v = shoulder_mid - hip_mid
    v_norm = norm(v)
    if v_norm == 0:
        return 0.0
    vertical = np.array([0, -1])  # y-down convention
    cosine = np.clip(dot(v, vertical) / v_norm, -1.0, 1.0)
    return degrees(arccos(cosine))

# Góc thân so với mặt đất
def trunk_angle_ground(shoulder_mid, hip_mid):
    return 90 - trunk_angle_vertical(shoulder_mid, hip_mid)


7.2. QUY ƯỚC NORMALIZE (2D MONOCULAR)

# Nguyên tắc: dùng shoulder_width làm scale chuẩn
#   - Ổn định hơn body_scale (chiều cao toàn thân)

7.5. EVENT DETECTION (cho temporal features)
--------------------------------------------------------------------------------
# Neo sự kiện chính
# KHÔNG dùng peak COM acceleration (đã chứng minh không đáng tin ở 30fps)
# KHÔNG dùng audio (video đầu vào không có tiếng)

--------------------------------------------------------------------------------
SỰ KIỆN 1: hand_off_frame (TAY RỜI ĐẤT)
--------------------------------------------------------------------------------
Định nghĩa:
    frame đầu tiên khi wrist_y < hip_y
    (cổ tay cao hơn hông trong mặt phẳng ảnh)

Công thức:
    hand_off = min{ f | wrist_y[f] < hip_y[f] }

Điều kiện hợp lệ:
    wrist_conf >= 0.5 VÀ hip_conf >= 0.5 tại frame đó
    Nếu không thỏa -> flag "hand_off_unreliable"

Độ tin cậy: CAO (dùng làm neo chính)

--------------------------------------------------------------------------------
SỰ KIỆN 2: onset_of_motion_frame (BẮT ĐẦU CHUYỂN ĐỘNG)
--------------------------------------------------------------------------------
Định nghĩa:
    frame đầu tiên sau hand_off khi COM bắt đầu dịch chuyển rõ rệt

Công thức:
    baseline_std = std(com_x[0 : hand_off])
    onset = min{ f > hand_off |
                 (com_x[f] - com_x[hand_off]) > 3 * baseline_std }

    Nếu baseline_std < 1px: dùng ngưỡng tuyệt đối 5px

Điều kiện hợp lệ:
    onset nằm trong [hand_off, hand_off + 12]
    Nếu không tìm thấy -> dùng hand_off làm onset

Độ tin cậy: TRUNG BÌNH

--------------------------------------------------------------------------------
SỰ KIỆN 3: rear_foot_off_frame (CHÂN SAU RỜI ĐẤT)
--------------------------------------------------------------------------------
Định nghĩa:
    frame đầu tiên khi cổ chân sau cao hơn mặt đất

Công thức chính (khi rear_ankle_conf >= 0.4):
    Δ = 0.05 * shoulder_width_px
    block_y = rear_ankle_y tại frame "Sẵn sàng" cuối cùng
    rear_foot_off = min{ f | rear_ankle_y[f] < block_y - Δ }

FALLBACK (khi rear_ankle_conf < 0.4 ở > 20% frame):
    # Trường hợp VĐV quay lưng về camera: chân sau bị chân trước
    # che hoàn toàn -> rear_ankle_y nhảy lung tung, không tin được.
    # Dùng tín hiệu thay thế: đùi sau bắt đầu đưa ra trước.

    hip_thigh_angle[f] = góc giữa đùi sau và trục dọc cơ thể
    baseline_angle = hip_thigh_angle tại frame "Sẵn sàng" cuối cùng
    baseline_std   = std(hip_thigh_angle trước hand_off)

    rear_foot_off_fallback = min{ f > hand_off |
        |hip_thigh_angle[f] - baseline_angle| > 3 * baseline_std }

    Nếu không tìm được -> dùng hand_off làm rear_foot_off
    Flag: "rear_foot_off_from_fallback"

Độ tin cậy: TRUNG BÌNH
    (thấp hơn khi dùng fallback)

--------------------------------------------------------------------------------
SỰ KIỆN 4: front_foot_off_frame (CHÂN TRƯỚC RỜI ĐẤT)
--------------------------------------------------------------------------------
Định nghĩa:
    frame đầu tiên khi cổ chân trước cao hơn mặt đất

Công thức:
    block_y_front = front_ankle_y tại frame "Sẵn sàng" cuối cùng
    front_foot_off = min{ f | front_ankle_y[f] < block_y_front - Δ }

RÀNG BUỘC:
    rear_foot_off PHẢI xảy ra TRƯỚC front_foot_off >= 1 frame
    Nếu không -> flag "leg_order_violation"

Độ tin cậy: TRUNG BÌNH

--------------------------------------------------------------------------------
SỰ KIỆN 5: launch_frame (THỜI ĐIỂM BỘC PHÁT)
--------------------------------------------------------------------------------
KHÔNG dùng:
    - Peak COM acceleration toàn video
    - Audio onset (video không tiếng)

PHƯƠNG PHÁP: 3-tier fallback chain (thuần pose)

TIER 1 — Multi-signal visual (confidence: HIGH)
    Cửa sổ: [onset_of_motion, onset_of_motion + 8]
    Điểm score cho mỗi frame:
        +2 nếu 30° <= torso_angle <= 55°
        +2 nếu rear_knee_angle >= 150°
        +1 nếu hip_omega > 0.7 * max(hip_omega trong cửa sổ)
        +1 nếu com_x > com_x[hand_off]
    Chọn frame có score cao nhất, ưu tiên gần hand_off.
    Chấp nhận nếu score >= 4/6.

TIER 2 — Hip/thigh angular velocity (confidence: MEDIUM)
    Dùng khi Tier 1 fail.
    combined = normalize(hip_omega) * normalize(thigh_omega)
    Chọn frame có combined cao nhất.
    Chấp nhận nếu combined > 0.6.

TIER 3 — First movement after hand_off (confidence: LOW)
    Dùng khi Tier 2 fail.
    Lấy frame đầu tiên sau hand_off thỏa 1 trong 3:
        com_x[f] - com_x[hand_off] > 2% shoulder_width
        torso_angle[f] > torso_angle[hand_off] + 5°
        hip_omega[f] > 1.5 * mean(hip_omega trước hand_off)

FAIL — Không tìm được
    Trả về None, flag "launch_not_found"
    KHÔNG chấm sub-phase Bộc phát
    Vẫn chấm Vào chỗ + Sẵn sàng

ĐẦU RA BẮT BUỘC:
    launch_frame, method, confidence
    method     ∈ {tier1_*, tier2_*, tier3_*, launch_not_found}
    confidence ∈ {high, medium, low, none}

GHI VÀO BÁO CÁO:
    launch_detection_method = <method>
    launch_confidence       = <confidence>

7.7. XỬ LÝ TỐC ĐỘ KHUNG HÌNH (FPS HANDLING)
--------------------------------------------------------------------------------
# Áp dụng cho video FPS < 60 (đặc biệt 30fps)
# Vấn đề: khoảng cách frame ~33ms -> tín hiệu pose bị "thô"
#         -> slope (đạo hàm) rất nhiễu, dễ false positive

NGUYÊN TẮC:
    Trước khi tính slope cho BẤT KỲ temporal feature nào,
    PHẢI làm mịn tín hiệu gốc.

CÁC BƯỚC XỬ LÝ (thứ tự bắt buộc):

  Bước 1: Nội suy (nếu có NaN)
      - Linear interpolation, giới hạn gap <= 5 frame
      - Không nội suy gap > 5 frame (đánh dấu missing)

  Bước 2: Làm mịn tín hiệu (chọn 1 trong 2)
      a) Moving Average (đơn giản, nhanh)
           window = 3 frame (cho 30fps)
           window = 5 frame (cho 60fps)
           smoothed[i] = mean(signal[i-k : i+k])

      b) Savitzky-Golay filter (tốt hơn, giữ được đỉnh)
           window_length = 5 (30fps), 7 (60fps)
           polyorder     = 2
           -> dùng scipy.signal.savgol_filter
           KHUYẾN NGHỊ: dùng Savitzky-Golay cho feature quan trọng
                        (step_length, cadence)

  Bước 3: Tính slope trên tín hiệu ĐÃ LÀM MỊN
      - KHÔNG tính slope trên tín hiệu thô

  Bước 4: Kiểm tra slope có ý nghĩa thống kê không
      - Nếu slope nằm trong nhiễu (|slope| < std của slope baseline)
        -> coi như không đổi, không kết luận "tăng" hay "giảm"

CẤU HÌNH ĐỀ XUẤT:

    | FPS | Filter       | Window | Polyorder |
    |-----|--------------|--------|-----------|
    | 30  | Savitzky-Golay|  5    |   2       |
    | 60  | Savitzky-Golay|  7    |   2       |
    | 120 | Savitzky-Golay|  9    |   2       |

LƯU Ý CHO CÁC FEATURE CỤ THỂ:

    step_length_trend:
        - Đo trên 5-8 bước đầu
        - Làm mịn riêng từng chuỗi step_length
        - Tính slope trên chuỗi đã mịn
        - Nếu FPS < 60: giảm tolerance xuống 2% (thay vì 3%)

    cadence_trend:
        - Đo trên 5-8 bước đầu
        - Làm mịn riêng chuỗi cadence
        - Nếu FPS < 60: KHÔNG chấm cadence_trend
          (vì 30fps không đủ độ phân giải để đo chính xác)
          -> chỉ ghi INFO

    trunk_angle_vertical_trend:
        - Làm mịn chuỗi góc thân
        - Ít bị ảnh hưởng FPS hơn (tín hiệu chậm, biên độ lớn)

CẢNH BÁO ĐỘ TIN CẬY:
    FPS < 60: flag "low_fps"
              - Vẫn chấm được feature góc (D1)
              - Giảm confidence cho feature slope (D2)
              - KHÔNG chấm cadence_trend
